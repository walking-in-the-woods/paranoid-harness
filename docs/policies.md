# Политики доступа к файлам

Правится в `config/fs_policy.yaml`. Директория монтируется read-only,
перезапуск контейнера не требуется — новый REPL подхватит изменения.

## Три списка

```yaml
root: /workspace

whitelist:
  - "**"

blacklist:
  - "**/.git/**"
  - "**/*.key"

writable:
  - "output/**"
  - "notes/**"
  - "*.md"
  - "*.txt"
```

- **`whitelist`** — что модель может видеть вообще. Если файл не
  матчится ни одним шаблоном, доступа нет (read и write).
  **Пустой список означает «ничего не разрешено»**. Отсутствие ключа
  даёт дефолт `["**"]`.
- **`blacklist`** — что запрещено, даже если прошло whitelist.
  Применяется после whitelist. Пустой список = ничего не запрещено.
- **`writable`** — что модель может предлагать к записи. Пустой
  список = запись везде запрещена. На чтение не влияет.

## Glob-синтаксис

| Шаблон | Матчит |
|---|---|
| `*` | один сегмент, кроме `/` |
| `**` | любое число сегментов, включая ноль |
| `?` | один символ, кроме `/` |
| `docs/**` | всё внутри `docs/`, но не сам `docs` |
| `**/*.md` | любой `.md` на любой глубине |
| `*.md` | только `.md` в корне `root` |

## Расширения на запись

Помимо списков, работает `WRITE_EXT_BLOCK` в `harness/fs_guard.py`:

- `.sh`, `.bash`, `.zsh`, `.fish`, `.ksh`
- `.exe`, `.bat`, `.cmd`, `.ps1`, `.vbs`
- `.py`, `.js`, `.ts`, `.rb`, `.go`, `.rs`, `.lua`
- `.php`, `.jsp`, `.cgi`, `.pl`
- `.whl`, `.egg`

Модель может **читать** любые из них. Запись блокируется независимо
от `writable`.

## Подводные камни

- **`workspace/` не должен быть симлинком на `$HOME`.**
- **Уже существующие файлы.** Guard проверяет только то, что модель
  **предлагает записать**.
- **Проверка на чтение не зависит от существования файла.**
- **TOCTOU в `_tool_list_dir`.** Для single-user локальной системы
  не критично.
