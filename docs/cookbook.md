# Рецепты

Практические задачи с готовыми формулировками. Все — в предположении,
что файлы лежат в `workspace/input/`, а результат идёт в
`workspace/output/`.

## Обработка документов

### Суммировать статью

```
прочитай input/article.md и напиши резюме на русском в output/summary.md.
Резюме — не больше 300 слов, три ключевые мысли отдельными пунктами.
```

### Выделить ключевые термины

```
прочитай input/paper.md, найди все незнакомые термины и оформи как
глоссарий в output/terms.md. Формат: **термин** — определение (одно
предложение).
```

### Сравнить два документа

```
прочитай input/version_a.md и input/version_b.md, найди различия
и оформи как output/diff_report.md. Структура: общее, различия,
рекомендация.
```

## Работа с кодом

### Объяснить модуль

```
прочитай input/module.py и напиши объяснение в output/explain.md.
Аудитория — разработчик, не знакомый с проектом. Не пересказывай код
строка за строкой, объясни назначение и ключевые решения.
```

### Найти потенциальные проблемы

```
прочитай input/service.py, найди места, где возможны ошибки обработки
исключений, гонки, утечки ресурсов. Оформи как output/review.md.
Не выдумывай проблемы — только то, что реально видно в коде.
```

### Сгенерировать тесты

```
прочитай input/parser.py, предложи набор тест-кейсов. Оформи как
output/test_cases.md: список с входом, ожидаемым поведением и кратким
обоснованием. Код не пиши — только описания.
```

## Извлечение структуры

### Список из текста

```
прочитай input/meeting_notes.txt, извлеки все задачи в формате
чеклиста в output/tasks.md. Для каждой: что сделать, кто ответственный
(если указан), срок (если указан).
```

### Таблица из прозы

```
прочитай input/features.md, оформи как markdown-таблицу в
output/features_table.md. Колонки: функция, статус, ограничения.
```

### JSON из документа

```
прочитай input/catalog.txt, оформи как валидный JSON в output/catalog.json.
Схема: [{"name": str, "category": str, "price": number}]. Только JSON,
без пояснений.
```

## Переводы

### Перевод с сохранением структуры

```
прочитай input/doc_ru.md, переведи на английский, сохрани markdown-разметку,
код-блоки и ссылки. Результат — output/doc_en.md.
```

### Терминологический перевод

```
прочитай input/technical.md, переведи на русский. Технические термины
(API, JSON, container, proxy) оставляй на английском. Результат —
output/technical_ru.md.
```

## Внешние API

### Погода

```
вызови api_call с route="weather", params={"latitude": 55.75,
"longitude": 37.62, "current": "temperature_2m"}. Оформи ответ
человекочитаемо в output/weather.md.
```

Доступные параметры Open-Meteo: `latitude`, `longitude`,
`current`, `hourly`, `daily`, `timezone`.

### Перевод через MyMemory

```
вызови api_call route="translate", params={"q": "Hello world",
"langpair": "en|ru"}. Покажи перевод.
```

### Тестовые данные

```
вызови api_call route="fake-data", method="GET". Покажи первые
три записи в виде таблицы.
```

## Цепочки

Одна сессия — одна запись. Для многошаговой работы используйте `/reset`:

```
>>> прочитай input/raw.txt и выдели ключевые идеи в output/ideas.md
[NEW FILE, ...]
code> A3B7C9E1
[OK] output/ideas.md

>>> /reset

>>> прочитай output/ideas.md и сгруппируй идеи по темам в output/themes.md
```

## Что улучшает результат

- **Явный формат вывода.** «Markdown-таблица», «JSON», «чеклист» —
  работают лучше, чем «оформи красиво».
- **Явная аудитория.** «Для разработчика», «для менеджера» — меняет
  тон и уровень деталей.
- **Ограничения.** «Не больше 300 слов», «только 5 пунктов»,
  «без примеров кода».
- **Явный путь.** Всегда пишите `output/имя.md`, иначе модель
  выберет что-то сама, и вы получите `REJECTED: path not in writable`.

## Что не работает

- **«Отредактируй все файлы в input/»** — упадёт на лимите одной
  записи в сессии. Разбивайте.
- **«Запусти скрипт»** — модель не выполняет код. Она может
  подготовить `.txt` со скриптом, вы запустите вручную.
- **«Пойди в интернет и найди»** — без явного route в `api_call`
  модель не имеет доступа к сети.
