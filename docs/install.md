# Установка

Инструкция по развёртыванию вынесена в отдельный документ, чтобы
держать её синхронной с текущей версией `setup.sh`. Здесь — только
контекст.

## Что понадобится

- Ubuntu 22.04 / 24.04 LTS (или Debian-совместимая)
- `sudo`
- ~10 ГБ свободного места
- Python 3.12 (для юнит-тестов на хосте)
- Docker 24+ с Compose v2

## Проверка целостности setup.sh

`bootstrap.sh` **не сверяет** sha256 `setup.sh` автоматически по
умолчанию — он делает только `bash -n` и grep по опасным
конструкциям. Сверка хеша — ваша ответственность:

```bash
sha256sum setup.sh
# сравните вручную с ожидаемым хешем из документации к релизу
```

**Где взять ожидаемый хеш:**

- Публикуется **вместе с `setup.sh`** в разделе релиза.
- Если публикация не содержит хеша — запросите у распространителя
  или зафиксируйте сами после первой проверки.

**Опциональная автоматическая проверка:**

`bootstrap.sh` умеет сверять sha256 `setup.sh`, если задан флаг:

```bash
./bootstrap.sh --verify-sha256=<ожидаемый-хеш>
```

**Формат хеша:** 64 hex-символа в нижнем регистре, без префикса
`sha256:`. Значение должно совпадать с выводом:

```bash
sha256sum setup.sh | awk '{print $1}'
```

При несовпадении скрипт падает до продолжения. Без флага —
печатает предупреждение и просит пользователя сверить вручную.

## Три шага

1. **Подготовка машины.** `install-machine.sh` ставит Docker и `uv`.
   Скрипт **идемпотентен**: проверяет версии Docker (≥ 24) и `uv`
   (`sort -V`, не откатывает более новые). Если Docker уже установлен
   — пропускает установку. Fingerprint GPG-ключа Docker сверяется с
   официальным — как при установке (fail-closed), так и при уже
   существующем keyring (warn + ask). Временные файлы создаются
   через `mktemp`.
2. **Создание файлов проекта.** `setup.sh` создаёт дерево и файлы.
   Сетевых вызовов не делает.
3. **Bootstrap.** `bootstrap.sh` создаёт `.env`, фиксирует Python-
   зависимости через `uv.lock` с cooldown 7 дней, прогоняет тесты,
   собирает образы, скачивает модель через изолированный updater
   (с опциональной digest-верификацией), поднимает контейнеры.

Полный текст скриптов — в инструкции, которая публикуется вместе с
`setup.sh`.

## Проверка после установки

```bash
# Изоляция: из контейнера harness нет выхода наружу
sudo docker compose exec harness python -c \
  "import socket; socket.create_connection(('1.1.1.1',53),timeout=2)"
# ожидается ошибка

# Модель загружена
sudo docker compose exec ollama-runner ollama list

# Юнит-тесты
pytest tests/ --ignore=tests/smoke -v
```

## Опционально: для машины с секретами

Digest-пиннинг базовых образов — до первого запуска. См. раздел A
отдельной инструкции.

Digest-пиннинг модели: задайте `HARNESS_MODEL_DIGEST` в `.env`. Как
получить digest — см. [Operations](operations.md). Помните про
ограничение: digest защищает от последующей подмены тега, но не от
компрометации реестра при первом pull.
