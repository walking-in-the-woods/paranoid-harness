# Использование

## Рабочая папка

`harness-project/workspace/` на хосте — это bind-mount в `/workspace`
внутри контейнера. Всё, что вы кладёте туда, сразу видно модели.

```bash
cd harness-project
mkdir -p workspace/input workspace/output workspace/notes
```

| Папка | Модель может |
|---|---|
| `workspace/input/` | Читать (не писать) |
| `workspace/output/` | Читать + предлагать запись |
| `workspace/notes/` | Читать + предлагать запись |
| `workspace/docs/`, `workspace/drafts/` | Читать + предлагать запись |
| `*.md`, `*.txt` в корне `workspace/` | Читать + предлагать запись |

`input/` специально исключён из `writable` — исходники остаются
нетронутыми.

## Типичный сценарий

```bash
# 1. Положить файлы
cp ~/Documents/report.md workspace/input/

# 2. Запустить REPL
sudo docker compose exec harness python -m harness.main
```

```
>>> прочитай input/report.md и напиши краткое резюме в output/summary.md

--- MODEL ---
Файл ожидает подтверждения.

============================================================
 PENDING WRITES — ПРОВЕРЬТЕ ПЕРЕД ПОДТВЕРЖДЕНИЕМ
============================================================
--- output/summary.md ---
[NEW FILE, 412 bytes]
# Краткое резюме
...
============================================================
 Введите код для ПРИМЕНЕНИЯ: 4F7A2C19
============================================================

code> 4F7A2C19
[OK] output/summary.md (412 bytes)
```

Результат сразу же лежит на хосте: `cat workspace/output/summary.md`.

## Несколько задач в одной сессии

Лимиты: **одна запись на сессию** и **read-after-write block**
(в текущей сессии нельзя прочитать только что записанный файл).
Между задачами — `/reset`:

```
>>> /reset
>>> прочитай output/summary.md и добавь раздел «Рекомендации»
```

## Отказ от записи

Если ввести не код, а что-то другое — файл не создаётся, ничего не
меняется. Это ожидаемое поведение, а не ошибка.

## Ограничения

- **Размер файла.** 200 КБ на чтение. Больше — резать на части или
  увеличивать `MAX_READ_BYTES` в `harness/agent_loop.py`.
- **Тип.** Только UTF-8. PDF/DOCX/PNG сначала конвертируйте.
- **Чёрный список.** Модель не увидит `.env`, `.git/`, `.ssh/`,
  `*.key`, `Makefile`, `package.json`, `pyproject.toml`,
  `.github/workflows/*` — даже на чтение.
- **Не кладите секреты** в `workspace/`: всё оттуда читается.

## Где смотреть логи

`logs/audit.jsonl` — JSONL с событиями `user_prompt`, `tool_call`,
`propose_write`, `apply_result`. Содержимое файлов и тел запросов
редактируется (`<N bytes>`), секреты не утекают.

`logs/gateway.jsonl` — JSONL с событиями `request`, `response`,
`auth_fail`, `rate_limited`. Ни промптов, ни ответов; только
метаданные, IP и HMAC-хеш промпта.

**Известное ограничение:** `path` в `audit.jsonl` **не
редактируется**. Если вы назвали файл
`notes/клиент_Иванов_договор.md`, это имя попадёт в `audit.jsonl`.
Учитывайте при именовании файлов в workspace.
