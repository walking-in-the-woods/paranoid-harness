# Глоссарий

## Компоненты

**harness** — контейнер с REPL и агентом. Обрабатывает ввод
пользователя, вызывает модель, диспетчеризует инструменты, показывает
diff и записывает файлы. Без доступа в интернет.

**ollama-runner** — контейнер с сервером Ollama. Работает с моделью,
не имеет сети наружу. Модель загружена в volume, проверенный по
sha256-манифесту.

**ollama-updater** — контейнер для загрузки моделей. Единственный
контейнер с интернетом (после прокси), который **не** подключён к
`internal-net`. Запускается по profile `updater`, в штатном режиме
остановлен. Работает с `read_only: true` — единственная запись
возможна в staging-volume и tmpfs.

**api-proxy** — единственная точка выхода в интернет. Слушает
локальный порт 8080, требует `X-Proxy-Secret`, использует фиксированный
словарь маршрутов.

**model-gateway** — FastAPI-гейтвей к Ollama. Единственный, кто
видит `ollama-runner`. Аутентифицирует клиентов (mTLS + токен),
применяет профиль (tools, system prompt, rate limit), пишет
`gateway.jsonl`.

**gateway-tls** — nginx с TLS-терминацией. Обязательный клиентский
сертификат (`ssl_verify_client on`). Пробрасывает сертификат в
`X-Client-Cert`, статус верификации — в `X-Client-Verify`.

## Сети и безопасность

**`internal-net`** — Docker-сеть с флагом `internal: true`. Означает,
что у контейнеров в этой сети **нет маршрута наружу** на уровне
iptables. Модель в такой сети физически не может обратиться в интернет.

**`external-net`** — обычная bridge-сеть. Используется только
`api-proxy` и `ollama-updater`.

**Nonce** — одноразовый код, который `ConfirmSession` генерирует и
показывает пользователю перед записью файла. Без правильного кода
запись не происходит. Защищает от программного вызова `confirm(True)`.

**`X-Proxy-Secret`** — HTTP-заголовок с секретом, которым `harness`
аутентифицируется в `api-proxy`. Без него прокси возвращает 403.

**`X-Gateway-Token`** — токен клиента, которым клиент
аутентифицируется в `model-gateway`. Второй фактор после mTLS.

**`X-Client-Cert`** — URL-encoded PEM клиентского сертификата,
пробрасываемый nginx. Python верифицирует подпись через `cryptography`.

**`X-Client-Verify`** — статус верификации клиентского сертификата
в nginx. Значение `SUCCESS` подтверждает, что TLS-handshake прошёл с
валидным клиентским сертификатом. `model-gateway` проверяет это
значение как defense-in-depth до верификации подписи в Python.

**Read-after-write block** — правило: файл, помеченный как записанный
в текущей сессии, нельзя прочитать в той же сессии. Защита от
самоинъекции. `_written_paths` хранит **канонические** пути, а не
сырые строки.

**`WRITE_EXT_BLOCK`** — список расширений, запрещённых для записи
(`.sh`, `.py`, `.exe`, `.js`, ...). Чтение этих файлов не блокируется.

**`writable`** — список путей, разрешённых для записи (`output/**`,
`notes/**`, `*.md`, ...). Не влияет на чтение.

**Blacklist** — список запрещённых путей, применяется **после**
whitelist. По умолчанию: `.env`, `.git/**`, `.ssh/**`, `*.key`,
`Makefile`, `package.json`, `pyproject.toml`, `.github/workflows/*`.

**Whitelist** — список разрешённых путей. **Пустой список = ничего
не разрешено.** Отсутствие ключа в policy → дефолт `["**"]`.

**`HARNESS_MODEL_DIGEST`** — опциональная переменная в `.env` для
проверки подлинности модели. Значение — `sha256:<hex>` или `<hex>`.
Проверяется в `sync-model.sh` через `ollama list --json`. **Ограничение:**
защищает от последующей подмены тега, но не от компрометации реестра
при первом pull.

**`ALPINE_IMAGE`** — переменная окружения для `sync-model.sh`. Задаёт
образ временного контейнера промоушена. По умолчанию `alpine:3.19`
(мутабельный тег, предупреждение в stderr). Для production —
`alpine@sha256:<digest>`.

**`--verify-sha256=<hash>`** — флаг `bootstrap.sh`. Опциональная
автоматическая проверка SHA256 `setup.sh`. Формат: 64 hex-символа
в нижнем регистре, без префикса `sha256:`.

**`GATEWAY_HMAC_KEY`** — HMAC-ключ `model-gateway` для `prompt_hash`
в `gateway.jsonl`. Должен быть ≥32 символов.

**`prompt_hash`** — HMAC-SHA256 с length-prefix от потока
`(role, content)` всех сообщений. Содержимое промптов не логируется;
хеш позволяет находить дубли и replay независимо от модели.

## Формат данных

**`<tool_result trust="untrusted">`** — обёртка, в которую
`HarnessAgent` заворачивает все данные от инструментов. Модель видит
их как data-блок и не должна интерпретировать как инструкции.

**`shown="N"`** — атрибут тега `<tool_result>` для `list_dir`:
сколько элементов реально показано. Метаданные в атрибуте, не в теле.

**`truncated="true"`** — атрибут тега `<tool_result>` для `list_dir`:
список был обрезан по лимиту.

**`neutralize_data_block`** — функция `InjectionGuard`, которая
экранирует XML-теги ролей и заменяет тройные бэктики в данных,
прежде чем они попадут в контекст модели.

**`scan_payload`** — проверка содержимого файла, которое модель
предлагает записать, на опасные паттерны (`curl|sh`, `chmod +x`,
fork bomb, `eval(`, `subprocess.`).

**NFKC-нормализация** — приведение Unicode к канонической форме.
Ловит гомоглифы и fullwidth символы до сравнения путей и текста.

**Гомоглифы** — символы разных алфавитов, визуально неотличимые.
Пример: `а` (U+0430, кириллица) и `a` (U+0061, латиница). NFKC
нормализует их к одной форме.

## Агент и инструменты

**Tool calling** — механизм, при котором модель возвращает не текст,
а структурированный вызов функции. `harness` исполняет вызов,
возвращает результат в контекст, модель продолжает.

**`list_dir`** — инструмент: список файлов и подкаталогов в
`/workspace/`.

**`read_file`** — инструмент: чтение UTF-8 файла. Лимит —
`MAX_READ_BYTES` (200 КБ).

**`propose_write`** — инструмент: предложить запись. Одна запись на
сессию. Файл не создаётся до подтверждения nonce.

**`api_call`** — инструмент: запрос к внешнему API через прокси.
Параметры: `route`, `method`, `params`, `body`. Route должен быть в
`ROUTES` прокси.

**`MAX_TOOL_ROUNDS`** — лимит числа раундов «модель → вызов инструмента
→ результат → модель» в одной задаче. По умолчанию 6.

**`canonical_rel`** — метод `HarnessAgent`, возвращающий
канонический posix-путь относительно workspace.

**mTLS** — mutual TLS. Клиент предъявляет сертификат, подписанный CA
проекта; nginx проверяет его при handshake, `model-gateway`
верифицирует подпись в Python.

## Файлы

**`pyproject.toml`** — описание Python-проекта. Зависимости проекта
живут здесь. Содержит `[tool.uv]` с настройками `uv`.

**`uv.lock`** — lock-файл `uv` с SHA256 для каждого транзитивного
пакета. Установка идёт только через `uv sync --locked`.

**`fs_policy.yaml`** — политики доступа к файлам: whitelist,
blacklist, writable.

**`gateway_clients.yaml`** — профили клиентов гейтвея: `name`,
`token_sha256`, `tools_enabled`, `allowed_tools`,
`forced_system_prompt`, `requests_per_minute`, `max_concurrent`,
`allow_stream`.

**`audit.jsonl`** — JSONL-лог событий `harness`. Пишется вне
`workspace/`. Для критичных событий — с `fsync`, для информационных —
только `flush`. **Известное ограничение:** `path` не редактируется.

**`gateway.jsonl`** — JSONL-лог событий `model-gateway`. Ни промптов,
ни ответов; метаданные, IP, HMAC-хеш.

**`ollama-models-verified.sha256`** — манифест sha256 снапшота
модели, посчитанный при промоушене в runner-volume.

**`config/logrotate.harness`** — шаблон конфига logrotate для
ротации `logs/audit.jsonl` и `logs/gateway.jsonl`.
